| 问题 | 原因 | 现状 / 建议 |
|------|------|-------------|
| Magic Link / Google 首次登录回到 `/login?error=auth_failed` 或需登两次 | PKCE cookie 时序、callback 只处理 `code` 未处理 `token_hash`、cookie 未写入 redirect 响应、**且 `AuthContext` 只在挂载时 `getUser()` 检查一次、role=null 即被 `/listings` 踢回 `/guest`** | callback 已修复双路径 + cookie 绑定；**`AuthContext` 已改为订阅 `onAuthStateChange`（`INITIAL_SESSION`/`SIGNED_IN`），session 注水前不会锁定 role=null，竞态已消除**；若仍复现，检查 Supabase Site URL、邮件链接域名与 Vercel 环境一致 |
| 登录成功却落在 `/guest`（无侧边栏） | Google OAuth 曾用 `next=/` → 中间件 `/` → `/guest` | **已修复**：OAuth 改为 `next=/listings` |
| `/listings` 闪一下再跳 Guest | `AuthContext` 加载中 `role=null`，`listings/page.tsx` 误判未登录 `router.replace('/guest')` | **已修复**：`AuthContext` 在 `onAuthStateChange` 解析出 session 前保持 `loading=true`，`/listings` 期间显示进度条而非误跳；未登录时 `return null` 避免闪烁 |
| 根路径 `/` 永远进 Guest | `middleware.ts` 无条件 `pathname === '/'` → `/guest` | 设计如此（公开入口）；**勿**把 OAuth/Magic Link 的 `next` 设为 `/` |
| 美化改动影响业务逻辑 | 纯 CSS/布局 | 新增行为：无租约空状态「去找房源」按钮（`router.push('/listings')`）；其余为显示层 |

## 1. 房源列表性能优化

**当前状态：** PropertyListings 组件一次性加载全部房源数据到内存，所有卡片同时渲染到 DOM，没有任何分页、虚拟滚动或图片懒加载。

**触发条件：** 房源数量超过 100 套时开始需要关注，超过 200 套会明显卡顿。

### 第一阶段：图片懒加载 + 分页（推荐优先实施）

**触发条件：** 100+ 套房源

**改动内容：**
- 给所有房源卡片的 `<img>` 标签加上 `loading="lazy"` 属性，让浏览器自动延迟加载视口外的图片
- 添加分页组件（每页 24 套），用户点击页码切换，避免一次性渲染大量 DOM 节点
- 改动范围小，只需修改 `PropertyListings.tsx` 中的网格渲染部分

**预期效果：** 初始加载只渲染 24 张卡片（~720 个 DOM 节点），图片按需加载，页面流畅度大幅提升。

### 第二阶段：Supabase 服务端分页 + 搜索下推

**触发条件：** 500+ 套房源

**改动内容：**
- 将 `supabase.from('units').select('*')` 改为 `supabase.from('units').select('*', { count: 'exact' }).range(offset, offset + limit)`
- 将搜索筛选从前端 `.filter()` 下推到数据库层（`.ilike('community.name', '%keyword%')`）
- 分页状态（页码、每页数量）反映到 URL query params，支持直接链接分享

**预期效果：** 每次只传输 24 条数据，网络传输量降低 95%+，数据库查询效率也更高。

### 第三阶段：虚拟滚动

**触发条件：** 1000+ 套房源，或需要无限滚动体验

**改动内容：**
- 安装 `react-virtuoso`（或 `@tanstack/react-virtual`）
- 将网格/列表替换为虚拟滚动容器，只渲染视口内可见的卡片
- DOM 节点数恒定在 ~50 个左右，不随数据量增长

**预期效果：** 即使 10000 套房源，页面也保持流畅，内存占用恒定。

## 2. 实时更新（Supabase Realtime）

**当前状态：** 房源数据（`units`、`communities` 表）没有 Supabase Realtime 订阅。用户需要手动刷新才能看到新房源。

**触发条件：** 多个中介同时管理房源，或者租客需要及时看到新房源时。

**改动内容：**
- 在 `PropertyListings.tsx` 中添加 Supabase channel 订阅：
  ```typescript
  supabase.channel('public:units')
    .on('postgres_changes', { event: '*', schema: 'public', table: 'units' }, () => {
      loadListings(); // 重新加载房源列表
    })
    .subscribe();
  ```
- 订阅 `communities` 表的变更
- 组件卸载时清理 channel

**预期效果：** 新房源上线、状态变更时，所有在线用户的浏览页面自动更新，无需手动刷新。
